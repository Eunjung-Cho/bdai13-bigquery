# 6주 핵심 정리

6주 동안 익힌 흐름을 다시 살펴봅니다. 질문을 정하고, 필요한 데이터를 골라 계산하고, 숫자가 맞는지 확인한 뒤 다른 사람에게 보여 주는 과정입니다.

| 회차 | 남겨야 할 습관 | 확인 질문 |
| --- | --- | --- |
| 1 | 열 이름과 읽을 데이터 크기부터 확인 | 이 열은 실제로 있고, 값은 숫자인가 글자인가? |
| 2 | 무엇을 세고 무엇으로 나눌지 정하기 | 금액, 건수, 고객 수를 같은 거래 조건으로 구했는가? |
| 3 | 키와 조인 전후 숫자 비교 | 고객, 카드를 붙여도 거래액이 유지되는가? |
| 4 | 기간과 집단으로 분해 | 변화가 어디서 일어났고 어디까지 해석할 수 있나? |
| 5 | 자주 볼 결과를 작은 표로 저장하기 | 표의 한 줄에 무엇을 담았고, 다음 조회에서 다시 쓸 수 있는가? |
| 6 | 앱과 SQL의 숫자 대조 | 필터를 바꿔도 같은 정의가 유지되는가? |

## 발표 전에 다시 읽을 문장

- 실행됐다고 올바른 SQL은 아닙니다.
- NULL은 ‘값을 모름’입니다. 금액을 모른다고 0원은 아니고, 사기 여부를 모른다고 정상 거래도 아닙니다.
- 복합 키에서 조건 하나가 빠지면 행과 금액이 늘어날 수 있습니다.
- `LAG`는 이전 행을 반환하며, 자동으로 이전 달을 찾아주지 않습니다.
- 논리 뷰는 재사용을 돕지만 비용을 자동으로 낮추지 않습니다.
- 전체 객단가는 총금액을 총거래 건수로 나눕니다. 전체 사기율도 사기 건수와 라벨 확인 건수를 각각 더한 뒤 나눕니다.
- AI가 붙인 원인 설명은 데이터 표에서 바로 확인되는 사실과 다릅니다.
- 공개 Streamlit 앱은 집계 마트를 읽고, 인증값은 Secrets에 보관합니다.
