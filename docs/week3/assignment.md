# 3주차 과제. 연결한 데이터로 질문에 답하기

[강의](lecture.md) · [실습](lab.md) · [프로젝트](../project.md)

예상 소요 시간은 90–120분입니다. 질문 2개가 필수이며 마지막 질문은 선택입니다. 결과 숫자의 크기보다 분석 조건과 조인 검증을 설명하는 것이 목표입니다. 마감과 제출 채널은 강사 공지를 따릅니다.

## 공통 조건

- 2018-01-01 이상, 2019-01-01 미만의 거래를 사용합니다.
- 날짜와 금액이 유효한 거래, errors가 NULL 또는 빈 문자열인 교육용 승인 거래를 선택합니다.
- 환불을 포함한 순거래액을 사용하며 거래당 금액은 순거래액/건수입니다.
- users 단일 키와 cards 복합 키의 유일성을 먼저 검사합니다.
- 읽기 원천은 `finda-13-2026.tabformer`입니다. 실제 준비 상태는 [환경 안내](../setup.md)를 확인하고 원본은 수정하지 않습니다.

수업의 완성 SQL을 출발점으로 사용해도 됩니다. 질문 1은 연결한 속성을 `card_type`으로, 질문 2는 성별을 채널로 바꾸는 식으로 한 부분씩 수정하세요. 수정한 이유를 설명하는 것이 빈 화면에서 외워 쓰는 것보다 중요합니다.

## 질문 1. 카드 유형에 따라 거래 패턴이 다른가? — 35분

카드 유형(`card_type`)별 순거래액, 거래 건수, 거래당 순거래액, 활성 고객 수를 구하세요. 두 개 이상의 유형을 비교하고, 관측된 차이에 대해 추가로 확인할 질문을 제시합니다.

**필수 조건**

- (1) transactions에 cards를 복합 키로 LEFT JOIN합니다.
- (2) 연결되지 않은 카드는 “카드 정보 미상”으로 보존합니다.
- (3) 전체 조인 전후 행 수와 금액 차이를 제출합니다.
- (4) 같은 고객이 여러 카드 유형에 등장할 수 있으므로 유형별 활성 고객 수를 단순 합산하여 전체 고객 수라고 쓰지 않습니다.

**힌트:** 먼저 고객 번호 하나에 카드가 몇 장 있는지 떠올려 보세요. 거래와 카드의 연결 조건이 하나라면 두 번째 조건을 확인합니다. 카드 유형 문자열의 종류는 원본에서 직접 확인합니다.

## 질문 2. 연령대별로 온라인과 오프라인 소비가 어떻게 다른가? — 35분

스냅샷 연령대 × 채널별 순거래액과 거래 건수를 구하세요. 연령대 하나를 골라 채널 차이를 설명하고, 고객 수의 차이 또는 환불 포함 여부가 해석에 줄 수 있는 영향을 적습니다.

**필수 조건**

- 온라인은 `Online Transaction`, 오프라인은 `Swipe Transaction`과 `Chip Transaction`, 나머지는 미분류입니다.
- 연령 미상과 채널 미분류를 집계에서 보존합니다.
- 세그먼트 전체의 금액과 건수 총합을 조인 전 기준값과 대조합니다.
- 스냅샷 나이를 거래 당시 나이로 서술하지 않습니다.

**힌트:** 수업의 연령대 쿼리에 채널 CASE를 더하되, 두 테이블에 같은 이름의 컬럼이 있다면 별칭을 붙입니다. 결과표의 연령대 순서는 문자열 정렬일 수 있으므로 숫자 순서가 필요한 경우 정렬용 값을 별도로 정의합니다.

## 질문 3. 관측 기간 미사용 카드의 정의를 바꾸면? — 선택 15분

“전체 관측 기간 미사용”과 “2018년 미사용” 카드 수를 비교하세요. 2018년 거래가 관측된 카드는 전체 기간 거래도 관측되므로, 동일한 유효 조건이라면 2018년 미사용 집합이 전체 기간 미사용 집합보다 작아질 수 있는지 생각해 봅니다. 카드 발급 시점이 없어서 판단할 수 없는 부분을 적습니다.

## AI 사용 및 검증 기록 — 20분

생성형 AI를 활용하되 결과를 복사한 것만으로 완료하지 않습니다. [AI 검증 안내](../reference/ai-verification.md)의 형식으로 아래 네 항목을 남깁니다.

| 항목 | 제출할 내용 |
| --- | --- |
| 생성 요청 | 스키마, 지표, 조건을 포함한 프롬프트 |
| AI 생성 부분 | 최초 쿼리 또는 해당 구간 |
| 검증 증거 | 키 유일성, 전후 행 수와 합계, 연결 실패 수 |
| 수정 및 판단 | 수정한 줄과 이유; 수정 불필요했다면 통과 근거 |

AI에 실습 데이터의 개별 거래 행, 개인 계정 정보, 토큰을 보내지 않습니다. 스키마와 작은 가상 사례만으로도 키 오류를 검증할 수 있습니다.

## 제출 전 체크

- [ ] 날짜 범위, 유효 금액, 승인 대리 정의, 환불 처리를 명시했다.
- [ ] 카드 복합 키를 두 조건으로 연결했다.
- [ ] 키 중복 및 NULL, 전후 행 수/합계, 연결 실패를 확인했다.
- [ ] 미상 그룹을 제외했다면 제외 전후 수와 이유를 적었다.
- [ ] 고객 수의 비가산성과 스냅샷 연령 한계를 설명했다.
- [ ] AI 생성 부분과 실제 검증 증거를 구분했다.
- [ ] 관측된 차이를 인과 또는 차별적 의사결정의 근거로 쓰지 않았다.
