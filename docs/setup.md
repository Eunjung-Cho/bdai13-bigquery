# 개강 전 환경 준비

첫 수업 전에 Google 로그인과 BigQuery 접속을 확인해 둡니다. 준비에는 약 30–45분이 걸립니다. **이 수업을 시작하려고 개인 결제 정보를 등록할 필요는 없습니다.**

## 1. 준비물과 프로젝트의 역할

| 준비물 | 사용하는 이유 | 완료 기준 |
| --- | --- | --- |
| Google 계정 | BigQuery, 대시보드 로그인 | Chrome에서 로그인 가능 |
| 생성형 AI 도구 1개 | SQL 초안 작성과 검증 연습 | 텍스트 질문 가능 |
| 개인 GCP 프로젝트 | SQL 실행과 개인 결과물 저장 | BigQuery 쿼리 편집기 열림 |
| 공유 데이터 접근 권한 | 강사가 준비한 세 테이블 조회 | 스키마와 미리보기 확인 |

BigQuery의 데이터는 큰 보관함 안에 폴더와 표가 들어 있는 모습으로 생각하면 쉽습니다. **프로젝트**는 큰 보관함, **데이터셋**은 표를 모아 둔 폴더, **테이블**은 엑셀처럼 행과 열로 된 표입니다. SQL은 데이터를 찾아 계산해 달라고 쓰는 명령문이고, 이 명령문을 **쿼리**라고도 부릅니다. 어느 표를 읽을지는 다음 주소로 알려 줍니다.

```text
프로젝트.데이터셋.테이블
bdai13-bigquery.tabformer.transactions   ← 강사가 읽기를 허용한 원본
YOUR_PROJECT.bdai13                     ← 개인 뷰와 마트를 저장할 공간
```

**데이터가 있는 프로젝트와 쿼리를 실행하는 프로젝트는 다를 수 있습니다.** 쿼리 사용량은 실행 프로젝트에 연결됩니다. 테이블을 다른 프로젝트에서 읽는다고 그 원본 소유자가 학생의 실행 비용을 자동으로 부담하지 않습니다.

## 2. BigQuery 샌드박스로 시작하기

1. [Google Cloud Console](https://console.cloud.google.com/bigquery)에 로그인합니다.
2. 본인 프로젝트를 만들거나 실습용 프로젝트를 선택합니다. 표시 이름과 프로젝트 ID는 다릅니다. SQL에는 **프로젝트 ID**를 씁니다.
3. BigQuery 화면으로 이동해 샌드박스 안내를 확인합니다. 기존 유료 프로젝트를 선택했다면 샌드박스와 비용 조건이 다릅니다.
4. 쿼리 편집기를 열고 다음 문장을 실행합니다.

```sql
SELECT
    'BDAI 13기' AS course,
    2 + 3 AS first_result;
```

실행하면 `BDAI 13기`와 `5`가 한 줄에 나옵니다. 아직 강의 데이터를 읽지 않아도 실행할 수 있는 계산입니다. 이 결과가 보이면 로그인과 쿼리 편집기 사용 준비가 된 것입니다.

!!! note "샌드박스의 범위"
    샌드박스는 결제 정보를 등록하지 않고 BigQuery를 연습하는 환경입니다. 무료 범위는 한 달에 조회할 때 처리하는 데이터 1TiB, 저장해 두는 데이터 10GiB입니다. TiB와 GiB는 파일 크기를 나타내는 단위이며, 조회량과 저장량은 따로 셉니다.

    테이블, 뷰, 파티션에는 60일 만료가 적용됩니다. 뷰는 다시 쓸 SQL에 이름을 붙여 저장한 것이고, 파티션은 큰 표를 날짜 같은 기준으로 나눈 구간입니다.

    실시간으로 데이터를 계속 넣는 기능(스트리밍)이나 기존 행을 추가, 수정, 삭제하는 명령(DML)은 제한됩니다. 수업에서는 주로 조회 명령인 SELECT를 쓰고, 5주차에 CREATE VIEW와 CREATE TABLE AS로 결과를 저장합니다. 개강 전에는 [현재 샌드박스 조건](https://docs.cloud.google.com/bigquery/docs/sandbox)에서 무료 한도와 제한을 확인하세요.

## 3. 공유 데이터에 연결하기

강사가 공지할 정보는 다음 네 가지입니다. 임의의 값으로 추측하지 마세요.

| 필요한 정보 | 자료 안의 표시 | 확인 방법 |
| --- | --- | --- |
| 원본 프로젝트 ID | `bdai13-bigquery` | 강사 공지 |
| 원본 데이터셋 ID | `tabformer` | Explorer에서 확인 |
| 데이터 위치 | `asia-northeast3` (서울) | 데이터셋 상세 정보 |
| 학생에게 부여된 읽기 권한 | 데이터 조회 가능 여부 | 테이블 스키마, 미리보기 |

왼쪽 탐색기(Explorer)에 프로젝트를 추가하고 `transactions`, `users`, `cards`를 찾습니다. **스키마(Schema)**에서는 열 이름과 값의 종류를 보고, **미리보기**에서는 실제 값 몇 줄을 볼 수 있습니다. 표의 가로줄은 ‘행’, 세로줄은 ‘열(column)’입니다. 원본을 내 컴퓨터에 복사할 필요는 없습니다. 열 이름이 [데이터 가이드](data-guide.md)의 설명과 같은지 확인하세요.

```sql
-- bdai13-bigquery를 강사가 공지한 프로젝트 ID로 바꿉니다.
SELECT table_name, column_name, data_type, is_nullable
FROM `bdai13-bigquery.tabformer.INFORMATION_SCHEMA.COLUMNS`
WHERE table_name IN ('transactions', 'users', 'cards')
ORDER BY table_name, ordinal_position;
```

오류가 나면 오류 메시지와 **실행 프로젝트/데이터 위치/테이블 주소**를 기록해 질문하세요. 로그인 이메일이나 식별자 목록을 공개 저장소에 올리지 않습니다.

## 4. 비용 안전장치 익히기

실행 버튼을 누르기 전에 BigQuery가 읽을 것으로 예상하는 데이터 크기를 [비용 기록표](templates/cost-log.md)에 적습니다. 실제로 읽은 양은 예상과 다를 수 있습니다. 특히 비슷한 값을 가까이 모아 저장한 클러스터링 테이블에서는 실행 전 예상치가 ‘최대로 읽을 수 있는 양’일 수 있습니다.

| 장치 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 테이블 미리보기 | 일부 행을 살펴봄 | SQL 집계 검증을 대신함 |
| 쿼리 검사, dry run | 문법과 예상 처리 바이트 확인 | 비즈니스 지표가 옳은지 판단 |
| Maximum bytes billed | 설정한 상한을 넘는 쿼리 실행 제한 | 저장비, 다른 서비스 비용 전체 제한 |
| 예산 알림 | 설정 기준에 맞춰 알림 | 결제, 쿼리를 자동 중단 |

쿼리 설정에서 **최대 청구 바이트**를 확인하세요. 숫자는 바이트 단위입니다. 첫 탐색 때는 교사가 안내한 상한을 사용하며, 예상량보다 작아 실행이 거절되면 쿼리 범위를 먼저 살핍니다. 상한을 무조건 높이는 것이 오류 해결 방법은 아닙니다.

`LIMIT 100`은 결과 행을 줄이는 문법입니다. 일반적인 테이블에서는 결과가 100줄이어도 계산을 위해 선택한 열 전체를 읽을 수 있습니다. 이처럼 데이터를 읽는 작업을 ‘스캔’이라고 합니다. 필요한 열 선택, 실제 파티션 열의 기간 조건, 작은 집계 마트가 각각 무엇을 줄이는지 구분합니다.

## 5. 5주차 저장 공간 준비

5주차 전에 개인 프로젝트에 `bdai13` 데이터셋을 만듭니다. 데이터 위치는 원본 데이터셋과 같은 `asia-northeast3`(서울)로 설정합니다. 서로 다른 지역(리전)에 저장된 데이터를 한 쿼리로 조인하거나 잘못된 위치에 결과물을 만들면 실패할 수 있습니다.

CREATE는 새 뷰나 테이블을 만드는 명령입니다. 본인 데이터셋에 새 자료를 만들 권한이 있어야 합니다. 예제의 `YOUR_PROJECT`를 자신의 프로젝트 ID로 바꾼 뒤 실행하세요. 샌드박스 자료는 기간이 지나면 만료되므로, 나중에 다시 만들 수 있도록 SQL과 집계 결과를 따로 보관합니다.

## 6. Streamlit 직접 연결 준비

6주차는 Streamlit으로 앱을 만듭니다. BigQuery Python 클라이언트는 결제 계정 없는 샌드박스 사용도 지원합니다. 개인 무료 실행 프로젝트와 자신의 집계 마트를 사용하고, 공개 앱의 서비스 계정, 조회 권한, Secrets를 5주차 과제 기간에 준비합니다.

기본 경로는 **BigQuery 집계 마트 → Python 조회 → Streamlit Community Cloud**입니다. 서비스 계정 사용이 어려우면 **Colab 본인 로그인 → 집계 결과를 DuckDB 파일로 저장 → 같은 Streamlit 앱**의 예비 경로를 사용합니다. DuckDB 파일에는 저장할 때의 결과가 담깁니다. 사진처럼 그때의 상태를 남긴 사본을 ‘스냅샷’이라고 합니다. 새 결과를 보려면 파일을 다시 만들어야 하며, CSV로 바꾸는 과정은 없습니다.

서비스 계정은 앱이 데이터를 읽을 때 사용하는 프로그램용 계정입니다. Secrets는 앱의 인증키를 코드 밖에 보관하는 설정 공간입니다. 상세 단계와 기본 앱은 [Streamlit과 데이터 연결](reference/dashboard-connection.md)에 있습니다. GCP 인증 설정은 제공 안내를 따라가고 Python 전체를 새로 학습할 필요는 없습니다. 앱은 원본 2,400만 건을 전부 읽지 않고 작은 집계 마트만 읽습니다.

## 자주 막히는 지점

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 프로젝트가 안 보임 | 로그인 계정, 프로젝트 ID, Explorer 추가 여부 |
| Access Denied | 원본 읽기 권한과 실행 프로젝트의 작업 권한을 따로 확인 |
| Not found in location | 데이터셋의 위치와 쿼리 실행 위치 |
| 열을 찾을 수 없음 | 실제 Schema와 자료의 열 이름 차이 |
| Maximum bytes 초과 | SELECT 열, 기간, 필터와 상한값 |
| 테이블이 사라짐 | 샌드박스 만료와 저장한 CREATE SQL |
| 앱의 BigQuery 접속 실패 | 실행 프로젝트, 리전, 서비스 계정 조회 권한, Secrets |
