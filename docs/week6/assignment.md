# 6주차 최종 제출 · 숫자의 근거를 보여 주는 앱

[프로젝트 안내](../project.md) · [실습](lab.md)

수업 후 약 60–90분 동안 발표 피드백을 반영하고 제출 파일을 정리합니다. 추가 기능을 늘리기보다 SQL·정의·앱 숫자의 일치를 우선합니다.

## 질문 1 다른 사람이 앱에서 질문의 답을 찾을 수 있는가

앱 URL과 프로젝트 README를 제출합니다. 질문 1개, 지표 2–3개, 차트 2개, 필터 1개 이상을 포함합니다. 동료가 처음 열고 어떤 기간·집단의 수치인지 설명할 수 있는지 확인하세요. 직접 연결인지 DuckDB 스냅샷인지, 데이터 취득/갱신 방식도 기록합니다.

## 질문 2 화면의 숫자를 SQL로 재현할 수 있는가

전체·특정 월·특정 채널 중 두 조건 이상에서 금액·건수·비율을 대조합니다. AI가 수정한 부분 1개와 직접 검증한 증거를 붙입니다. 데이터 없음과 분모0은 잘못된 0%로 숨기지 않습니다.

## 제출 목록

- 질문·지표 정의·분석 기간·한계가 담긴 README.
- 분석 SQL, 검증 SQL, 뷰와 마트 생성 SQL.
- Streamlit 코드·requirements와 실제 앱 URL.
- AI 생성 부분·수정·검증 기록.
- SQL와 앱의 대조표 및 동료 접근 확인 결과.

실제 서비스 계정 키, Secrets 파일, 개인 거래 행은 제출하지 않습니다. DuckDB 파일을 공개 저장소에 올릴 때는 공개 가능한 집계만 포함하는지 확인합니다. 앱이 생성되어 URL은 있지만 실제 데이터가 안 보이면 연결 미완료로 표시합니다.

## 최종 피드백 질문

어떤 질문에 답했나요? 숫자를 신뢰할 근거는 무엇인가요? 아직 알 수 없는 것은 무엇인가요? AI의 오류를 어떤 근거로 수정했나요? 이 네 가지를 자신의 말로 설명할 수 있으면 이번 과정의 결과물을 갖춘 것입니다.

개인 분석 기록과 팀 발표의 제출 단위·마감은 강사 공지를 따릅니다. 이 안내는 공식 성적 배점을 새로 정하지 않습니다.
