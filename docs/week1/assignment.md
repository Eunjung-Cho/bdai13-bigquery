# 1주차 과제 · 다음 분석가에게 데이터 인수인계하기

[강의](lecture.md) · [실습](lab.md) · [AI 검증 기록](../reference/ai-verification.md)

**권장 90분: 필수 질문 2개 70분 + 선택 도전 20분.** 강의의 완성된 SQL에서 한 부분씩 바꾸어도 됩니다. 외운 문법의 수보다, 질문과 조건이 맞고 검증 근거가 남았는지를 봅니다.

## 필수 질문 1 · 2018년 거래액 분석을 시작할 준비가 되었는가? · 40분

다음 주 담당자가 2018년 업종별 거래액을 분석하려고 합니다. “데이터를 사용할 수 있다”는 말에 어떤 조건이 붙는지 인수인계 메모를 작성하세요.

1. 원본 전체 행 수와 유효한 2018년 날짜의 행 수를 확인합니다.
2. 전체 행 중 금액을 해석할 수 없는 행, 음수 금액 행, 날짜를 해석할 수 없는 행을 확인합니다.
3. 데이터 함정 세 가지와 다음 분석에서 필요한 처리 방침을 적습니다.
4. NULL이나 변환 실패를 0으로 바꾸었을 때 생기는 해석 문제를 설명합니다.

실제 결과는 직접 실행해서 기록합니다. 공개 자료에 나온 “약 2,400만 건”을 실행 결과로 복사하지 않습니다. 전체 기준으로 계산한 결측 수와 2018년 기준 수치를 혼용하지 않습니다.

<details markdown="1">
<summary>시작 힌트</summary>

[실습 B1·B2](lab.md)의 SQL을 그대로 출발점으로 사용합니다. 거래액을 산출하라는 과제가 아니므로 아직 `SUM`을 추가하지 않아도 됩니다. 먼저 “불가 금액 = 원본 NULL + 빈 문자열 + 기타 변환 불가일 수 있음”을 확인하고 범위를 명시합니다. 음수를 삭제할지 결정하기 전에 환불 포함 순거래액과 양수 거래액이 다른 지표임을 적습니다.

</details>

## 필수 질문 2 · AI가 만든 ‘2018년 거래 건수’는 같은 질문에 답하는가? · 30분

AI 도구 하나에 동일한 비즈니스 질문을 두 번 요청합니다. 첫 번째에는 질문만, 두 번째에는 실제 스키마와 날짜 조건을 함께 제공합니다.

- 원본 날짜 열은 `year`, `month`, `day`입니다.
- 유효한 날짜가 2018-01-01 이상 2019-01-01 미만인 원본 행을 셉니다.
- 승인·금액·사기 조건은 추가하지 않습니다.
- 생성 SQL, 실행 전 검토, 실행 결과 또는 오류, 수정 사항을 남깁니다.
- 두 응답이 모두 맞았다면 맞다고 판단한 근거를 씁니다. 오류를 반드시 발견할 필요는 없습니다.

<details markdown="1">
<summary>검증 힌트</summary>

열 이름 → 자료형 → 날짜 변환 → 기간 → `COUNT(*)` 또는 `COUNTIF`의 조건 순으로 읽습니다. `COUNT(amount)`는 NULL 금액 행을 제외하므로 행 수와 다를 수 있습니다. 오류를 고친 뒤에는 1번 과제의 같은 범위 수치와 비교합니다. AI가 임의로 쓴 실행 결과는 지우고 본인 실행 결과로 교체합니다.

</details>

## 선택 도전 · 사용자 수와 카드 수는 어떻게 연결되는가? · 20분

`users`와 `cards`를 각각 조회하여 행 수, 키 결측, 키 중복 여부를 확인하세요. 조인 없이 답합니다. `cards.card_index`가 중복되는 사실만으로 데이터 오류라고 말할 수 없는 이유를 2–3문장으로 설명합니다.

<details markdown="1">
<summary>힌트</summary>

사용자는 `user_id`, 카드는 `user`와 `card_index`를 함께 묶어 확인합니다. `GROUP BY` 후 `HAVING COUNT(*) > 1`을 사용하면 중복 키 후보를 볼 수 있습니다. 중복이 없다는 결과도 중요한 관찰입니다. 원본 거래에서 같은 사용자·카드가 반복되는 것은 자연스러운 거래 기록일 수 있습니다.

</details>

## 제출 형식

`week1.sql`과 `week1-report.md` 또는 같은 내용을 담은 문서 하나를 제출합니다. 보고서는 질문 → 조건 → 결과 표 → 해석 → 검증 → AI 사용 기록 순으로 작성합니다. SQL과 결과를 대응시킬 수 있게 쿼리에 A, B 같은 이름을 붙입니다.

| 체크 | 제출 전 확인 |
|---|---|
| □ | 실제 실행한 SQL과 실제 결과가 대응한다 |
| □ | 원본 주소·실행 프로젝트·처리 바이트·캐시 여부를 기록했다 |
| □ | 전체와 2018년 집계 범위를 구별했다 |
| □ | 변환 실패를 0으로 바꾸지 않았다 |
| □ | 데이터 함정과 다음 처리 방침을 설명했다 |
| □ | AI가 생성한 부분과 검증·수정한 부분을 표시했다 |
| □ | 인증정보·학생 명단·서비스 계정 키를 포함하지 않았다 |

접속이 막혔다면 실행했다고 표시하지 않습니다. 오류 문구와 재현 단계, 실행 전 작성한 SQL을 남기고 강사에게 지원을 요청합니다. 공유 권한 문제가 해결된 뒤 실제 결과를 보완합니다.
